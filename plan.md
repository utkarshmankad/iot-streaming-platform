# Environmental IoT streaming platform implementation plan

**Version 0.1 · Baseline [specs.md v0.5](specs.md) and [architecture.md v0.5](architecture.md)**

Repository baseline: `architecture.md` is recorded in local commit `af3a48d`. This plan uses M0 for scaffolding and environment setup, then builds each feature on that foundation. Deployment means a local Docker Compose stack on the laptop. GitHub hosts the source and runs CI.

## How to work through the plan

Each checklist item is a short-lived branch and pull request from current `main`, named `<type>/<task-id>-<description>`. Use a Conventional Commit title and include the relevant spec IDs, verification evidence and any known limits. Split items that cannot land independently into smaller task IDs. Keep the task unchecked in its implementation PR. After GitHub confirms that PR merged into `main`, open a docs-only PR to check off the task and link the implementation PR in the Change history. The completion PR uses the same required CI and squash-merge rules. Keep unfinished feature paths behind configuration until they can pass a full smoke test.

Use a separate checkout for implementation. The hourly runner fetches and fast-forwards the laptop checkout of `main` at the start of each run and after a confirmed merge. It verifies that the local commit and tracked tree match `origin/main`. If local changes, a different branch or divergent commits prevent a safe fast-forward, report the blocker and preserve the checkout.

## M1 · Provision tenants and deliver the telemetry path

- [x] **M1.1 · Tenant and registry foundation.** Add Flyway migrations for tenant memberships, gateway and device assignment, sensor registry, schema-version metadata and sensor state. Implement tenant authorization, credential provisioning, broker topic ACL generation and verified gateway registry snapshots. Seed two tenants with overlapping sensor and event IDs. *(TEN-01–03, ING-04)*
- [x] **M1.2 · Payload contracts and generator.** Check in Protobuf messages, per-type validators and fixtures for all six simulated sensor types. Implement seeded one-hertz generation, byte accounting, heartbeats and durable simulator checkpoints and outbox. Publish over MQTT 5 and correlate application receipts separately from PUBACK. *(REQ-02–04, ING-01–02)*
- [x] **M1.3 · Gateway spool.** Implement MQTT subscriptions, topic/identity and schema checks, atomic SQLite enqueue, durable receipts, and per-tenant queue budgets. Flush HTTP Protobuf batches at 250 records or one second. Add bounded retries, fair live/replay scheduling and permanent rejection accounting. *(ING-01–02, TEN-02, OPS-04)*
- [x] **M1.4 · Idempotent backend ingest.** Create the TimescaleDB hypertable, tenant/time indexes, and receipt ledger. Revalidate events and transactionally commit ledger and reading changes. Return stable per-event outcomes for mixed batches. Test concurrent duplicates, changed-content conflicts and retries after a lost commit response. *(ING-01–03, AC-09)*
- [x] **M1.5 · Telemetry smoke and reliability verification.** Add CI tests for tenant MQTT isolation, simulator silence, gateway and broker restart, lost application receipt and backend/database failure. Assert a traceable terminal result for each generated event after drain. Wire the full-path smoke test into `CI gate`. *(FT-01–03, AC-02, AC-09–10)*

**Exit gate.** Two tenants send validated readings from the simulator through MQTT and the durable gateway to TimescaleDB. Restart and replay checks prove original event identity is preserved and duplicate rows are suppressed.

## M2 · Ship the trend API and React dashboard

- [x] **M2.1 · Analytics storage.** Implement per-tenant 15-minute continuous aggregates, a consistent raw-tail boundary, weighted rollups and durable repair for late events. Test UTC and Monday alignment, gaps, partial buckets and late arrivals. *(UI-02–03, AC-04)*
- [x] **M2.2 · Read API and sessions.** Complete browser OpenAPI definitions and implement tenant-aware login/session behavior, sensor list and trends endpoints. Enforce pagination, bucket alignment, 30-day history and ten-sensor query limits. Test boundary and error responses, tenant switching and isolation. *(UI-01–02, TEN-01–03)*
- [x] **M2.3 · Dashboard and performance gate.** Add tenant selection, registry and sensor status, the four trend resolutions, freshness, partial and empty buckets, polling and failures. Add browser and Gatling tests, including five concurrent readers during ingest. Wire short performance assertions into CI. *(UI-01–03, AC-01, AC-03–04, CI-01–02)*

**Exit gate.** The dashboard displays accurate tenant-scoped results at all four resolutions. Short load tests report ingest and trend latency and compare them with AC-03.

## M3 · Ship acknowledged controls, alarms and recovery

- [x] **M3.1 · Control APIs and durable command state.** Implement the command create/status API, idempotency, operator permissions, outbox, expiry and monotonic per-sensor versions. Add gateway polling and MQTT relay, durable simulator apply and acknowledgment. Verify retries, expired and superseded commands, and tenant boundaries. *(CTL-01–02, TEN-01–03, AC-05)*
- [x] **M3.2 · Control UI and liveness.** Add per-sensor on/off actions and show desired, pending and confirmed state. Distinguish stale readings, lost heartbeat and confirmed pause. Test the online five-second p95 command target and offline pending/expiry behavior. *(UI-01, CTL-01–02, AC-05)*
- [x] **M3.3 · Observability and alarms.** Add pipeline metrics, structured logs, daily exports and capacity alerts. Configure Prometheus rules, Alertmanager routing and a persistent SQLite alarm ledger independent of TimescaleDB. Test firing, resolution, duplicate notifications, receiver recreation, access control and missing-metrics behavior. *(OBS-01–04, AC-11)*
- [x] **M3.4 · Backup and restore tooling.** Add PostgreSQL base backup and continuous WAL archival, SQLite online queue snapshots, manifests, checksums and isolated restore commands. Document target storage, backup expiry, recovery reconciliation and stale-command prevention. Measure RPO, restore time and backlog drain separately. *(OPS-04–06, AC-07–08)*
- [x] **M3.5 · Fault suites and operational handoff.** Implement the remaining CI fault scenarios, package the pilot fault profile and runbook, and attach evidence per architecture §9. Test fault durations, alerts, tenant isolation and reconciled readings. Ensure CI artifacts are retained and confirm nightly checks and security jobs run. *(FT-01–03, AC-09–12, CI-02–03)*

**Exit gate.** A browser pause/resume round trip succeeds only after simulator confirmation. CI exercises the short failure suite, and all commands and evidence locations for the outage and restore drills are documented.

## M4 · Calibrate, pilot, soak and report

- [x] **M4.1 · One-hour calibration.** Measure original binary payload size, choose a one-hertz sensor count for 1 GB per active day across at least two tenants, and estimate raw, index, ledger, WAL, queue and backup growth. Record hardware, versions, Compose limits, seeds and headroom. *(REQ-03–04, OPS-01–02)*
- [x] **M4.2 · 24-hour steady pilot and 24-hour outage test.** Validate 1 GB/day ±5%, throughput, latency and resource headroom during 24 hours of steady ingestion. Align the pilot runbook with architecture FT-01G. In a separate fault window, disconnect the gateway from the backend and accumulate 24 active hours at the calibrated rate. Record laptop sleep and wake times separately, keep the link disconnected, and extend the same run to recover the active time. Verify the partition after wake and report the sleep gap. Measure peak backlog, replay rate and drain time while live ingestion continues. Verify chart repair and reconcile each tenant. Also run WAN-only isolation, a separate queue saturation case, an isolated restore from the independent encrypted backup and the alarm watchdog drill. The restore may use a freshly downloaded, client-side encrypted Google Drive copy. Run the local archive interruption check separately and record cloud transfer and internet dependency. Record actual gaps, RPO and recovery times. Fix failures and repeat affected checks. *(OPS-02–06, OBS-04, AC-02–03, AC-07–08, AC-11–12)*
- [ ] **M4.3 · Passive laptop soak, up to three elapsed days.** After M4.2 passes, run the calibrated multi-tenant workload in the background on the Mac. Generate readings and collect evidence while the Mac is awake and the local Docker stack is ready. Let the Mac sleep normally. Resume automatically in the same run with the same volumes after wake and stack readiness. Record sleep and service interruptions as gaps and count only actual generation toward active runtime. Stop the soak at 72 elapsed hours from first start, including sleep and downtime. If the deadline passes while the Mac is asleep, finalize on wake without restarting the soak. Record actual active hours, throughput per active day, per-tenant counts, storage growth, latency and alarms. Measure comparable trend queries at baseline, at daily checkpoints reached during active operation and in the final available sample. Hand preserved queues and evidence to M4.4 for drain and reconciliation. Verify sleep, automatic resume and expiry across sleep with a short local test. *(REQ-03–04, OPS-02–03, AC-02–06)*
- [ ] **M4.4 · Reconcile and publish the local run report.** Drain queues, reconcile identities and losses per tenant, verify restore evidence, and export CSV and Markdown covering volume, storage growth, performance, downtime, alarms and limits. Link each acceptance criterion to its evidence in the report. *(AC-01–12)*

**Exit gate.** The report records pass/fail and supporting evidence for every acceptance criterion. Performance and recovery targets are confirmed by observations from the actual laptop deployment.
